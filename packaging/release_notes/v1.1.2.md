## New
- **Portable mode (#9, #16):** put a file named `portable.txt`, or a folder named `portable`, next to the program. Everything then stays in that `portable` folder: settings, saves, the game built from your disc, shader caches and logs. Move the whole folder to another drive or PC and it keeps working; on a different graphics card only the shaders are prepared again.
  - F1 > Game > Data folder shows where your data lives.
  - It can also move an existing installation's data into the portable folder, or back to the system folder.
  - Updates keep a portable installation portable.
- **Recovery after a failed start:** if the game crashed or didn't get going last time, the next start offers to start normally, reset settings (a backup is kept), rebuild the game data, or put your saves aside (moved, never deleted).
- **Log file on Windows:** the game now writes `last_run.log` (and keeps `previous_run.log`) in its data folder, so you can attach it to bug reports. If the game ever stops making progress at start-up, the log says where it got stuck.

## Fixed
- **Anti-aliasing (#14):** on Linux/Vulkan, choosing 2x or 8x anti-aliasing made the game fail to start, every time. The menu now offers only the levels your graphics device supports. An unsupported saved level falls back to the nearest supported one, with a note in the menu, instead of crashing.
- **"command_processor: unknown opcode" (#17):** malformed graphics data no longer closes the game. It's skipped, logged with the details needed to track down the cause, and the game keeps running. A rare race between game loading and frame interpolation was also fixed.
- **Damaged settings.ini:** if the file is damaged (for example by a power cut), it's moved aside and the game starts with default settings.
- **Long folder paths on Windows:** updates and first-time setup work from deeply nested folders. If the folder is too deep for the graphics driver, the game now tells you to move it instead of closing silently.

## Known issues
- Steam Deck: some players report a soft lock after switching to 60 or 90 fps (#11). We couldn't reproduce it yet; a log from an affected Deck would help.
- The 2-player mode (Unused content) is unfinished.
