**Luigi's Mansion Recompiled 1.1.5** adds a macOS version and DSU controllers, fixes the memory growth over long sessions, the Linux/Steam Deck freeze above 30 fps, slow shader preparation and the music slider. On 1.1 or later, the game offers it in F1 > Game > Updates.

**No game data is included.** On first start the game asks for your own disc image (ISO/RVZ and other Dolphin formats) of the USA release (GLME01) and/or the European release (GLMP01). Read the README.txt in the package for requirements and details.

## New
- **macOS (Apple silicon, M1 or newer, macOS 13+)**, contributed by @NitrosGits (#31). It runs on Metal and builds the game on your Mac from your own disc, like the other versions. The package is built automatically from the same source, is not signed by Apple, and is tested by the community only: see its README.txt for the first start.
- **DSU controllers** (F1 > Controls > DSU), also from #31: use motion-capable pads through a DSU (cemuhook) server, on every system. GameCube controllers behind a server get the GameCube layout.
- **"Press F1 to open Settings"** shows in the top-left corner for the first few seconds of play. Turn it off in F1 > Visuals > General.

## Fixed
- **Memory grew the longer you played (#34).** Three causes:
  - A small piece of memory for every texture the game set up was never freed: about 12 MB a minute, whatever you were doing. A 30-minute session now stays flat.
  - Screen copies (shadows, the Game Boy Horror view) were kept in GPU memory for every map you had visited. Copies the game no longer uses are now freed.
  - Every shader compiled while "Preparing shaders" stayed in memory. A first start left 2 GB more in use than needed, and up to 11 GB with Enhanced lighting. That memory is now released once the shaders are built. With Enhanced lighting the first-start compile is also faster (254 → 105 s here), and quitting afterwards is immediate instead of taking up to 2 minutes.
- **Linux and Steam Deck: the picture froze above 30 fps (#2, #11)**, after START or the pause screen, while the music played on. A compatibility function for older Linux systems called itself endlessly when the game blended a frame. 1.1.4's change did not cure this. Reproduced and confirmed fixed on Linux.
- **"Preparing shaders" was slow on 60 Hz displays (#33).** The loading screen redrew so often that it held up the shader loading. Warm starts are now up to 4 times faster.
- **The music volume slider now covers all music (#29).** At 0, the game's sequenced music kept playing. Now music 0 is silent while sound effects stay. Checked on both discs.
- **Audio crackling (#25):** sound effects are no longer cut off when the game thinks the sound chip is overloaded, the sound buffer grows when the PC can't keep up, and loud moments are softly limited instead of clipping. We couldn't reproduce the crackling ourselves: if you still hear it, please attach `last_run.log` to #25.
